# 3인 편집실 (edit-writing-room)

## 적용 후 남는 결과

1. 지금 상태 — 중심 판단 한 문장 + 안정적인 지점
2. 독자가 막히는 곳 (3개 이내) + 구조 진단
3. 우선 수정 세 가지 — 현재 문장 → 수정 방향 문장 → 이유
4. 반드시 보존할 부분 + 구체화 필요 목록
5. 총평 — 전면 수정 필요 여부 판정

최종 원고는 사용자가 `반영해줘`라고 했을 때만 낸다.

## 3인의 정의

이름의 3인은 작가·독자·편집자다. 글 한 편에는 원래 이 세 자리가 필요한데, AI에게 맡기면 한 에이전트가 세 자리를 혼자 차지한다. 쓰고, 스스로 읽고, 스스로 잘 썼다고 판단한다. 이 스킬은 그 자리를 다시 갈라놓는다.

| 자리 | 누가 맡는가 | 결정하는 것 |
|---|---|---|
| 작가 | 사람(사용자) | 무엇을 쓸지, 경험을 어디까지 공개할지, 판단 강도, 발행 여부 |
| 독자 | 서브에이전트 | 어디서 막혔는지 (수정 권한 없음) |
| 편집자 | 서브에이전트 | 어떻게 고칠지 (사실·경험 추가 권한 없음) |

메인 에이전트는 네 번째 인원이 아니라 진행 담당이다. 원본을 잠그고, 두 역할을 순서대로 부르고, 결과를 점검해 작가에게 넘긴다. 작가의 자리를 대신하지 않는다. 원고의 관점, 경험 공개, 강한 판단, 게시 여부는 사용자가 결정한다.

## 핵심 개념

```text
작가(사용자)      원고·범위·승인
메인 에이전트     원본 잠금·조정·최종 점검
  → 독자 서브에이전트    반응과 막힘만 보고 (수정 금지)
  → 편집자 서브에이전트  독자 리포트를 반영해 수정 (내장 문체 기준 3층 적용)
  → 메인 에이전트        저자성·범위·사실 점검 후 작가에게 인계
```

독자와 편집자는 부모 대화를 모르는 새 문맥의 서브에이전트다. 역할 정의와 폴백 기준은 `references/` 세 파일에, 문체 기준은 `voice/`에 내장되어 있다. 메인은 이 스킬의 Base directory로 **절대 경로**를 만들어 역할 브리프와 문체 3층을 넘긴다. 다른 스킬은 호출하지 않는다. 폴백일 때만 최소 카드 본문을 프롬프트에 직접 넣는다.

## 호출 축 세 가지

이 스킬에는 다이얼이 세 개 있다. 셋은 서로 다른 것을 정하므로 하나의 `모드`로 묶어 부르지 않는다.

| 축 | 값 | 기본값 | 정하는 것 |
|---|---|---|---|
| 역할 | 독자 · 편집자 · 편집실 · 병렬 | 편집실 | 누가 원고를 보는가 |
| 출력 | 제안 · 선택반영 · 전체반영 | 제안 | 무엇이 돌아오는가 |
| 강도 | 최소 · 표준 · 구조 | 표준 | 어디까지 손대는가 |

축 사이에는 다음 구속이 걸린다.

- `역할 = 독자`이면 출력은 `제안`으로 고정한다. 독자는 수정 권한이 없으므로 다른 값을 묻지도 받지도 않는다. 강도 축도 적용되지 않는다.
- `출력 = 전체반영`은 사용자가 원고 전문을 요구했을 때만 연다. 추정으로 이 값에 들어가지 않는다.
- `출력 = 선택반영`은 제안을 낸 뒤 사용자가 번호를 고른 다음에만 들어간다 (STEP 5).
- `강도 = 구조`는 사용자가 명시했을 때만 연다.

`기준 축`(정본·폴백)은 사용자가 고르는 값이 아니라 STEP 0의 호출 결과로 정해진다. 위 세 축과 섞어 부르지 않는다.

## When to Use

- `3인 편집실로 봐줘`, `독자와 편집자에게 검토시켜줘`, `멀티 에이전트로 퇴고해줘`
- `40~50대 AI 입문 독자가 어떻게 읽을지 봐줘`
- `내 개인적인 생각은 살리고 편집해줘`
- 초안·칼럼·페이스북 글·블로그 글·브런치 글·에세이·책 한 챕터를 독자 검토 후 편집할 때

다음 요청은 전체 흐름 대신 축 값을 좁혀 이 스킬 안에서 처리한다.

| 상황 | 처리 |
|---|---|
| 맞춤법·오탈자 한두 곳, 지정 구간 부분 수정 | 역할 = 편집자, 강도 = 최소, 지정 구간만 |
| 문체 변환만 (독자 검토 불필요) | 역할 = 편집자, 강도 = 표준 |
| AI 흔적·금지어만 제거 | 역할 = 편집자, 강도 = 최소, voice 3층(`03-anti-traces.md`)만 적용 |
| 책 한 권 전체 검증·퇴고 | 챕터 단위로 나눠 한 편씩 진행 |
| 원고 없이 아이디어만 탐색 | 해당 없음 (일반 대화) |

이 스킬은 짧은 원고 또는 장편의 한 작업 단위에 쓴다.

## 중단 금지 규칙

이 스킬은 **어떤 경우에도 파일이 없다는 이유로 멈추지 않는다.** 문체 기준은 `voice/`에 내장되어 있고, 그 파일을 열지 못해도 최소 카드가 남는다.

산출물에 다음 문구를 쓰지 않는다.

```text
정본 파일을 첨부해주시면 이어서 진행하겠습니다
파일을 읽어야 시작 가능합니다
진행하시려면 다음 중 하나를 선택해주세요
정본 없이 진행하므로 다른 스킬로 전환합니다
```

파일 첨부 요구, 선택지 제시, 다른 스킬로의 전환 권유, 단계 보류는 모두 금지한다. 기준 파일이 없으면 아래 최소 기준으로 그대로 편집한다.

## 편집 기준 최소 카드 (항상 사용 가능)

`voice/` 파일을 열지 못했을 때 이것만으로 편집자 단계를 끝낸다. 상세는 `references/fallback-voice.md`.

## 실행 흐름

```text
STEP 0 기준 확보·기준 모드 결정
STEP 1 요청 확인·원본 잠금
STEP 2 독자 서브에이전트 호출 → 독자 리포트
STEP 3 편집자 서브에이전트 호출 → 수정 원고
STEP 4 메인 종합·하네스 점검 → 최종 출력
STEP 5 사용자 피드백 반영
```

# STEP 0. 기준 확보 (1회)

**메인 에이전트가 직접 수행한다.** 서브에이전트는 자기 작업 디렉터리 기준으로 상대 경로를 해석하므로, 절대 경로를 받아야 파일을 읽는다. 메인이 할 일은 **경로를 확보해 넘기는 것**이지 본문을 통째로 프롬프트에 붙이는 것이 아니다.

```text
1) 대화 첨부      기준 문서가 첨부돼 있으면 그것을 쓴다
2) 내장 기준      이 스킬의 Base directory를 BASE로 기록한다
                  → {BASE}/voice/ 파일 존재를 확인한다
                  → 메인은 판정 근거로 01-voice.md만 읽어 둔다 (기준 모드 종합 시 필요)
3) 실패           즉시 폴백 모드로 진행. 재시도·요청·보고 없음
```

### 서브에이전트에 넘기는 것

정본 모드에서는 **절대 경로 목록**을 넘긴다. 57KB를 프롬프트에 복사하지 않는다.

```text
{BASE}/voice/01-voice.md        1층 시선·어조·논리·리듬·마무리
{BASE}/voice/02-glossary.md     2층 단어·문장 선택
{BASE}/voice/03-anti-traces.md  3층 AI 흔적·금지어·계량
{BASE}/voice/04-examples.md     4층 승인 원문 (저자성 판정 근거)
```

경로는 반드시 절대 경로로 변환해 넘긴다. 상대 경로는 서브에이전트의 작업 디렉터리 기준으로 해석되어 실패한다. 역할 브리프(`references/reader-brief.md`·`references/editor-brief.md`)도 같은 방식으로 절대 경로로 넘긴다.

폴백 모드에서는 읽을 파일이 없으므로 **최소 카드 전문**을 프롬프트에 직접 넣는다.

### 역할별 조달 범위

STEP 1에서 역할이 확정되기 전이라도 호출 자체는 가볍다. 실제 3층 읽기는 편집자 단계가 있을 때만 필요하다.

| 역할 | 조달 |
|---|---|
| 독자 | BASE만 확보. 3층 경로는 넘기지 않는다 (독자는 편집하지 않는다) |
| 편집자 · 편집실 · 병렬 | BASE + 4개 경로 전부 |

### 실행 모드 표기 (필수)

산출물 말미에 아래 한 줄을 **항상** 붙인다. 성공·실패 모두 적는다.

```text
문체 기준: 내장 voice (1층·2층·3층 적용)
문체 기준: 폴백 최소 카드 (voice 파일 열기 실패)
```

일부 voice 파일만 열었으면 확보한 층만 경로로 넘기고, 나머지는 최소 카드의 해당 줄을 함께 넣는다. 이때 표기는 `문체 기준: 내장 voice (1층·3층) + 최소 카드 보완`처럼 실제 상태를 쓴다.

우선순위 충돌 시 판단 순서: 사실·원문 → 현재 사용자 지시 → 승인된 경험·표현 → 프로젝트·채널 기준 → 정본 3층 → 최소 카드.

# STEP 1. 요청 확인과 원본 잠금

받을 것 다섯 가지. 대화나 파일에서 이미 확인되면 다시 묻지 않는다. 없으면 한 번에 하나씩 묻는다.

| 항목 | 값 | 기본값 |
|---|---|---|
| 원고 | 본문 또는 절대 경로 | 필수 |
| 채널 | 범용·페이스북·블로그·브런치·책 | 원고에서 추정 후 확인 |
| 역할 | 독자 / 편집자 / 편집실 / 병렬 | 편집실 |
| 출력 | 제안 / 선택반영 / 전체반영 | 제안 |
| 강도 | 최소 / 표준 / 구조 | 표준 |

### 축 확정 선언 (필수)

호출문 한 줄에서 세 축을 모두 읽어낼 수는 없다. 추정한 값을 **작업 시작 전에 한 줄로 먼저 밝힌다.** 이 줄에서 사용자 의도와의 어긋남이 드러난다.

```text
역할: 편집자 · 출력: 제안 · 강도: 최소 · 채널: 블로그
```

호출문에 수정을 뜻하는 말(`고쳐줘`, `편집해줘`, `다듬어줘`)이 있어도 출력 축은 `제안`이 기본이다. 수정을 뜻하는 말과 원고 전문을 요구하는 말(`반영해줘`, `수정본 줘`, `전체 고쳐줘`)은 다르다. 앞엣것은 역할 축의 신호이고 뒤엣것만 출력 축을 `전체반영`으로 옮긴다.

선언 줄과 다른 값을 사용자가 원하면 그 자리에서 고쳐 받고 다시 시작한다. 작업 도중에 축을 바꾸지 않는다.

원본은 최신 사용자 제공본 또는 최신 승인본 하나로 잠근다. 이전 보조 초안에서 다시 시작하지 않는다. 두 서브에이전트에는 같은 원본을 전달한다.

# STEP 2. 독자 서브에이전트 호출

Agent 도구로 호출한다. `subagent_type`은 `general-purpose`를 쓴다.

프롬프트에 넣을 항목:

- `references/reader-brief.md`를 읽으라는 지시 (경로는 스킬 디렉터리 기준 절대 경로로 변환해 전달)
- 원고 전문 또는 절대 경로
- 채널과 글의 목적
- 반환 형식: 독자 리포트만

완료 기준: 모든 High·Mid 지적이 원고 위치와 연결되고, 수정문 없이 리포트만 돌아온다.

# STEP 3. 편집자 서브에이전트 호출

독자 리포트가 돌아온 뒤 순차 호출한다.

프롬프트에 넣을 항목:

- `references/editor-brief.md`를 읽으라는 지시
- **편집 기준** — 정본 모드는 STEP 0의 4개 **절대 경로**(01·02·03·04)를 넘기고 순서대로 읽으라고 지시한다. 폴백 모드는 최소 카드 **전문**을 프롬프트에 직접 넣는다
- 정본 모드일 때: 1층 보이스 → 2층 표현사전 → 3층 흔적 제거 → 4층 승인 원문 대조 순서로 적용하라는 지시. `Skill` 도구는 쓰지 말고 받은 경로만 읽으라고 명시한다
- AI 흔적 지수는 `03-anti-traces.md` §11 정의(범주 1~8 + §10 사전)로만 산출하라는 지시
- 편집 강도와 채널
- 원고 전문 또는 절대 경로
- 독자 리포트 전문 (`역할 = 편집자`·`역할 = 병렬`에서는 이 항목이 없다. 없으면 0층을 건너뛰고 원고만 독립 편집하라고 명시한다)
- 변경 금지 영역과 사용자 승인 문구
- 출력 축 (제안 / 전체반영)
- 완료 조건: 출력이 `제안`이면 수정 제안 3~5건을 `선행 → 현재 문장 → 수정 방향 문장 → 이유`로, `전체반영`이면 수정 원고 전문을 반환할 것. 자료 부족을 이유로 반환을 보류하지 말 것

서브에이전트가 파일을 못 읽었다고 보고하며 빈손으로 돌아오면 그 응답을 사용자에게 전달하지 않는다. 메인이 기준 본문을 넣어 즉시 재호출한다.

완료 기준: 독자 리포트의 High 항목을 반영하거나 보류 이유를 밝히고, 원고에 없는 경험·사실을 추가하지 않는다. 출력이 `제안`이면 원고 전문을 다시 쓰지 않는다. 고칠 문장만 인용하고 그 자리에 들어갈 완성 문장을 제시한다.

## 역할 = 병렬

사용자가 `병렬로`, `한 번에 독자와 편집자`, `빠르게`라고 명시하면 Agent 두 개를 한 메시지에서 동시에 호출한다. 이때 편집자는 독자 리포트를 받지 못하므로 원고만 독립 편집하고, 메인 에이전트가 두 결과를 대조해 반영한다. 기본값은 순차 호출이다.

# STEP 4. 메인 종합

편집자 결과를 그대로 전달하지 않는다. 다섯 항목을 점검한다.

1. 독자 지적과 수정 원고가 연결되는가.
2. 홍작가의 개인적 판단이 일반론으로 약해지지 않았는가.
3. 원문에 없는 경험·수치·인용·제품 사실이 생기지 않았는가.
4. 최신 사용자 승인 문구와 수정 범위가 보존됐는가.
5. 원고 본문과 내부 편집 보고서가 분리됐는가.

이어서 하네스 점검을 실행한다. 편집자가 자기 결과를 스스로 합격 처리하지 않도록, 이 점검은 메인이 다시 한다.

| 점검 | 합격 기준 |
|---|---|
| 금지어·상투어 | 0건 |
| 추상 형용사·모호 부사 | 0건 |
| AI 흔적 지수 | 수정 전 대비 하락, 등급 `낮음` 권장 |
| 사실 보존 | 수치·고유명사·인용·날짜 불일치 0건 |
| 분량 | 원문의 120% 이내 |
| 일반론 | 편집자가 사례를 지어 채우지 않고 `구체화 필요`로 남겼는가 |

미달 항목이 있으면 해당 항목만 수정 후 재점검, 최대 2회. 2회 후에도 남으면 위치와 사유를 보고한다.

## 출력 형식 — 제안 (기본값)

원고 전체를 고쳐서 내지 않는다. 어디를 어떻게 고칠지 짚어주고, 고칠지 말지는 작가가 정한다.

```markdown
## 지금 상태
[안정적인 지점 1~2줄. 이 글의 중심 판단 한 문장]

## 독자가 막히는 곳
[3개 이내. 각 항목은 위치 + 무엇이 안 보이는지]

## 구조 진단
[전체 흐름을 텍스트 다이어그램으로 그리고, 축이 엉키거나 연결이 빠진 지점만 지적]

## 우선 수정 세 가지

### 1. [수정 항목 이름]

선행: 없음 (또는 N번)

현재
> [원고 문장 그대로 인용]

수정 방향
> [고친 문장. 완성된 대체 문장으로 제시]

[왜 이렇게 바꾸는지 1~2줄]

### 2. …
### 3. …

## 반드시 보존할 부분
[원문 문장을 그대로 인용. 6개 이내]

## 구체화 필요
[작가가 경험·사례·수치로 채울 자리. 대신 쓰지 않는다]

## 총평
[전면 수정할 원고인지 아닌지 한 문단으로 판정. 무엇을 더하고 무엇을 덜어낼지]

## 점검 결과
[실행 모드(정본/폴백) + AI 흔적 지수 전→후 1줄]
```

제안 개수는 3개를 기본으로 하고 최대 5개를 넘지 않는다. 전면 수정이 필요한 원고라도 한 번에 다 내지 않고, 우선 세 개를 내고 반영 여부를 받은 뒤 다음 묶음으로 넘어간다.

각 제안의 `수정 방향`은 방향 설명이 아니라 **바로 붙여넣을 수 있는 완성 문장**으로 쓴다. `~를 구체화하면 좋겠습니다` 같은 지시형은 제안이 아니다.

## 출력 형식 — 반영 (선택반영·전체반영 공용)

출력 축이 `선택반영` 또는 `전체반영`일 때 쓴다. 전체반영은 사용자가 `반영해줘`·`수정본 줘`·`전체 고쳐줘`라고 했을 때만 열린다. 선택반영은 STEP 5에서 제안 번호를 받은 뒤에 들어간다.

```markdown
## 이 글의 중심 판단
[한 문장]

## 반영한 것
[3~5개. 수정 전 → 수정 후로 짝지어]

## 반영하지 않은 것과 이유
[전체반영은 있을 때만. 선택반영은 고르지 않은 제안 번호·이름·사유를 필수로 적는다]

## 최종 원고
[완성된 원고]

## 구체화 필요
[작가가 채울 자리]

## 점검 결과
[축 선언 + 실행 모드 + 반영 주체 + AI 흔적 지수 전→후 + 하네스 통과 여부 1줄]
```

`역할 = 독자`일 때도 리포트 원본을 그대로 내보내지 않는다. 메인이 `지금 상태`와 `독자가 막히는 곳`으로 압축하고, `[원고근거]`·`[독자추정]` 라벨이 붙은 상세 항목은 그 아래에 둔다.

# STEP 5. 사용자 피드백 반영

제안을 낸 뒤 사용자가 번호를 고르면 출력 축이 `선택반영`으로 넘어간다. 이 단계에서 피드백이 새지 않도록 실행 주체와 순서를 아래로 고정한다.

## 반영은 편집자 서브에이전트가 한다

메인 에이전트가 원고 문장을 직접 고쳐 넣지 않는다. 메인은 진행 담당이지 네 번째 인원이 아니다. 선택된 제안을 들고 편집자를 다시 호출한다.

재호출 프롬프트에 넣을 항목:

- `references/editor-brief.md` 절대 경로와 그 문서의 `선택 반영 재호출` 절을 적용하라는 지시
- STEP 1에서 잠근 원본 전문 또는 절대 경로
- 선택된 제안 전문 — 현재 문장·수정 방향 문장·이유를 그대로 넣는다. 요약하지 않는다
- 선택되지 않은 제안의 번호와 이름. **반영 금지 목록**으로 명시한다
- 최신 사용자 승인 문구와 변경 금지 영역
- 채널과 강도
- 완료 조건: 선택된 제안만 원고에 넣고, 그 밖의 구간은 원본 문장을 글자 그대로 둘 것

서브에이전트 호출이 불가능한 환경이면 메인이 반영하되, 산출물 말미에 `반영 주체: 메인 (서브에이전트 호출 불가)`를 적는다. 조용히 대신하지 않는다.

## 제안 간 의존 확인

제안은 서로 독립이 아니다. 앞 제안이 도입부 구조를 바꾸면 뒤 제안이 그 도입부를 전제로 쓰였을 수 있다.

- 제안을 낼 때 각 항목에 `선행: 없음` 또는 `선행: N번`을 적는다 (STEP 4 출력 형식)
- 사용자가 선행이 걸린 제안만 고르면 반영 전에 짝을 알린다 — `3번은 1번을 전제로 합니다. 1번 없이 3번만 넣으면 (위치)의 연결이 끊깁니다.`
- 알린 뒤에도 사용자가 3번만 원하면 그대로 반영하고, 끊긴 자리를 `구체화 필요`에 남긴다. 임의로 메워 넣지 않는다

## 승인본 고정

반영이 끝나면 그 결과가 새 원본이다. 승인본을 대화에만 두지 않는다.

- 원고가 프로젝트 폴더의 파일이면 같은 폴더에 `00 승인본.md`로 저장하고 `last_updated`를 적는다
- 원고를 대화 본문으로 받았으면 저장 여부를 한 번 묻는다. 사용자가 거절하면 저장하지 않고 넘어간다
- 다음 호출의 STEP 1은 이 승인본을 원본으로 잠근다. 이전 제안본이나 보조 초안에서 다시 시작하지 않는다

## 선택 구간 재점검

STEP 4의 하네스 점검은 편집자 결과에 대해 돌았다. 부분 반영은 새 문장과 원본 문장이 섞이므로 한 번 더 본다. 대상은 **바뀐 구간과 그 앞뒤 문단까지**이며, 원고 전체를 다시 세지 않는다.

| 점검 | 합격 기준 |
|---|---|
| 금지어·상투어 | 바뀐 구간 0건 |
| 사실 보존 | 바뀐 구간의 수치·고유명사·인용·날짜 불일치 0건 |
| 리듬 | 삽입 문장과 원본 문장 사이에 같은 길이·역할 3연속이 생기지 않았는가 |
| 분량 | 원문의 120% 이내 |

AI 흔적 지수는 구간 재점검에서 다시 산출하지 않는다. 척도가 원고 전체 1,000자 환산이므로 구간만으로는 전/후 비교가 성립하지 않는다.

## 거절 기록

- `1번과 3번만 반영해줘` 같은 선택을 받는다. 고르지 않은 제안은 같은 원고에서 다시 꺼내지 않는다
- 사용자가 거절 사유를 말하면 그 문장을 그대로 남긴다. 사유가 없으면 `사유 없음`으로 적고 추측해 채우지 않는다
- 거절 기록은 `voice/05-corrections.md`의 교정 후보와 같은 자리에 `거절 패턴` 항목으로 쌓는다. 승격 조건은 표현 교정과 같다 — 다른 원고에서 반복 확인 + 사용자 승인
- 한 번의 선호나 한 번의 거절을 곧바로 공용 규칙으로 만들지 않는다

## 이어지는 라운드

- 세 개를 다 반영한 뒤 남은 항목이 있으면 다음 세 개를 제안한다. 이때 원본은 방금 고정한 승인본이다
- 사용자가 문장이나 판단을 직접 고치면 그 수정본이 최신 승인본이 된다
- 여러 원고에서 반복된 절차만 이 스킬에 승격한다

## 호출 예시

```text
이 원고를 3인 편집실로 검토해줘.
→ 역할: 편집실 · 출력: 제안 · 강도: 표준
```

```text
독자 검토만 해줘. 문장은 고치지 마.
```

```text
편집자만 불러서 최소 강도로 봐줘. 내 판단과 문단 순서는 그대로 둬.
→ 역할: 편집자 · 출력: 제안 · 강도: 최소
```

```text
1번과 3번만 반영해줘.
→ 역할: 편집자 · 출력: 선택반영 · 강도: 직전 라운드 값 유지
```

```text
구조 편집까지 허용할게. 40~50대 AI 입문 독자가 따라오도록 제목과 도입부터 다시 봐줘.
```

## 자주 나오는 실패

1. 독자가 편집까지 함 — 독자는 반응과 막힘만 보고한다.
2. 편집자가 저자의 생각을 일반론으로 바꿈 — 판단 강도는 보존하고 근거와 위치만 정리한다.
3. 서브에이전트가 부모 대화를 안다고 가정함 — 역할·원고·채널·승인 문구를 프롬프트에 전부 넣는다.
4. 매번 병렬 호출함 — 독자 반응을 반영해야 하면 순차로 부른다.
5. 정본이 없다고 편집을 멈추고 첨부를 요구함 — 최소 카드로 그대로 진행한다. 이것이 가장 자주 나오는 실패다.
6. 서브에이전트에게 상대 경로를 넘김 — 서브는 경로를 자기 작업 디렉터리 기준으로 읽는다. 메인이 STEP 0에서 확보한 절대 경로를 넘긴다.
7. 독자 시뮬레이션을 실제 조사처럼 보고함 — `[독자추정]`과 `[원고근거]`를 구분한다.
8. 한 번의 교정을 즉시 메모리·사전에 저장함 — 승인과 반복성을 확인한 뒤 승격한다.
9. 최종 원고에 작업 보고서를 섞음 — 보고서와 본문을 분리한다.
10. 일반론을 편집자가 사례로 채움 — 구체 사례·수치가 없는 자리는 `구체화 필요`로 남기고 작가가 채운다.
11. 묻지도 않았는데 원고 전문을 고쳐서 냄 — 출력 축의 기본값은 `제안`이다. 전문은 `반영해줘`를 받은 뒤에 낸다.
12. 수정 방향을 지시문으로 씀 — `구체화하면 좋겠습니다`가 아니라 붙여넣을 완성 문장을 준다.
13. 역할·출력·강도를 한 덩어리 `모드`로 읽음 — 축이 셋이다. STEP 1에서 세 값을 따로 선언한다.
14. `고쳐줘`를 출력 축 신호로 읽음 — 그것은 역할 축 신호다. 출력 축을 옮기는 말은 `반영해줘`·`수정본 줘`·`전체 고쳐줘`뿐이다.
15. 메인이 선택 반영을 직접 손으로 넣음 — 편집자를 재호출한다. 호출이 불가능하면 반영 주체를 산출물에 밝힌다.
16. 선택되지 않은 제안이 슬며시 들어감 — 반영 금지 목록으로 명시해 넘긴다.
17. 승인본을 대화에만 둠 — 다음 라운드의 원본이 풀린다. 파일로 고정하거나 저장 여부를 묻는다.
18. 부분 반영 뒤 점검을 건너뜀 — 바뀐 구간과 앞뒤 문단을 다시 본다.

## 최종 체크

- [ ] 역할·출력·강도 세 축을 한 줄로 선언하고 시작했다
- [ ] `역할 = 독자`일 때 출력 축을 묻거나 적용하지 않았다
- [ ] `출력 = 전체반영`에 추정으로 들어가지 않았다
- [ ] 최신 원고 또는 승인본이 원본으로 잠겼다
- [ ] 독자 페르소나가 40~50대 AI 입문·초급 사용자로 유지됐다
- [ ] 독자 지적이 원고 위치와 근거를 포함하고 직접 편집하지 않았다
- [ ] 편집자가 독자 리포트와 원고를 함께 받았다 (`역할 = 편집자`·`역할 = 병렬`은 해당 없음)
- [ ] STEP 0에서 `voice/` 파일을 확인해 실행 모드를 결정했다
- [ ] 산출물 말미에 실행 모드 한 줄을 붙였다
- [ ] 호출 실패를 이유로 작업을 중단하거나 파일을 요구하지 않았다
- [ ] 산출물에 첨부 요청·선택지 제시·다른 스킬 전환 권유 문구가 없다
- [ ] 편집 기준을 정본 모드에서는 절대 경로로, 폴백 모드에서만 본문으로 서브에이전트에 넘겼다
- [ ] 최종 출력에 중심 판단 한 문장과 보존 문장 목록이 있다
- [ ] 실제 장면·개인적 생각·판단 강도가 보존됐다
- [ ] 원고에 없는 경험·사실·수치·인용이 추가되지 않았다
- [ ] 편집 강도와 요청 범위가 지켜졌다
- [ ] 리포트·편집 설명·최종 원고가 구분됐다
- [ ] 하네스 점검(금지어·추상 표현 0건, 사실 보존, 분량)을 통과했다
- [ ] AI 흔적 지수 전/후를 보고했고 지수가 하락했다
- [ ] 일반론을 지어 채우지 않고 `구체화 필요`로 남겼다
- [ ] 출력이 `제안`일 때 원고 전문을 다시 쓰지 않았다
- [ ] 제안이 3개(최대 5개) 이내이고 각 제안에 현재 문장·수정 방향 문장·이유가 있다
- [ ] 총평에서 전면 수정 필요 여부를 판정했다
- [ ] 메인 에이전트가 작가의 결정(관점·경험 공개·판단 강도·발행)을 대신하지 않았다
- [ ] 각 제안에 `선행` 표기가 있고, 선행이 끊긴 선택을 반영 전에 알렸다
- [ ] 선택 반영을 편집자 재호출로 처리했거나, 불가능한 경우 반영 주체를 밝혔다
- [ ] 선택되지 않은 제안을 반영 금지 목록으로 넘겼고 원고에 들어가지 않았다
- [ ] 반영 결과를 승인본으로 고정했거나 저장 여부를 물었다
- [ ] 바뀐 구간과 앞뒤 문단에 선택 구간 재점검을 돌렸다
- [ ] 거절 사유를 그대로 기록했고 추측해 채우지 않았다
- [ ] 최종 승인과 게시 판단은 사용자에게 남아 있다
