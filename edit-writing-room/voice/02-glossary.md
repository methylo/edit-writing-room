# 02 표현사전 — 단어·문장 선택

> `v1.6.0` · 갱신 2026-08-01 · 출처: hong-voice-reference v1.6.0 내장 사본(2026-09-23). edit-writing-room 편집 기준으로 쓴다.

> 2층. 홍작가가 실제로 쓸 단어와 문장을 고르고, 낯선 표현을 교체한다.
> 시선·리듬은 `01-voice.md`, 흔적 제거는 `03-anti-traces.md`가 맡는다.
> 적용 범위: 블로그·페이스북·브런치·에세이·책 원고·일반 콘텐츠

## 0. 이 사전의 역할

이 문서는 홍작가 명의의 한국어 글을 쓸 때 **어떤 표현을 고르고, 어떤 표현을 걷어낼지** 판단하는 공용 기준이다.

세 문서는 역할이 다르다.

| 문서 | 역할 |
|---|---|
| `01-voice.md` | 글의 시선·논리·리듬·문단 흐름을 정한다 |
| `02-glossary.md` | 홍작가가 실제로 쓸 법한 단어와 문장을 고른다 |
| `03-anti-traces.md` | AI식 과장·완곡·추상 표현을 최종 제거한다 |
| `04-examples.md` | 홍작가가 승인한 실제 문단과 판단 이동을 보여준다 |

이 사전의 목표는 문장을 매끈하게 만드는 데 있지 않다. **글쓴이가 실제로 소유할 수 있는 말로 판단을 남기는 것**이 목표다.

## 1. 적용 우선순위

```text
사실·원문
→ 현재 사용자 지시
→ 승인된 경험·사용자 표현
→ 04-examples (승인 원문)        ← 규칙 3층보다 위
→ 프로젝트별 기준·표현사전
→ 채널별 글쓰기 스킬
→ 01-voice
→ 02-glossary
→ 03-anti-traces
```

- 사실, 출처, 사용자 원문의 의미를 가장 먼저 보존한다.
- 사용자가 현재 요청에서 명시한 지시와 직접 고친 문장을 우선한다.
- **`04-examples.md`는 규칙 3층보다 위다.** 규칙과 승인 원문이 갈리면 승인 원문을 따른다.
- `05-corrections.md`의 확정 교정은 `04-examples`와 같은 층으로 본다.
- 프로젝트에 별도 용어 기준이 있으면 공용 사전보다 우선한다.
- 채널별 스킬은 구조·분량·형식을 정하고, 공용 보이스와 이 사전은 문체와 실제 문구를 고른다.
- 금지어를 기계적으로 지우지 않는다. 원래 의미와 판단을 다른 문장으로 살린다.

## 2. 홍작가 표현의 중심

### 기본 문장 이동

```text
경험형: 실행·장면 → 기대 또는 막힘 → 실제 어긋남 → 현재 판단
개념형: 문제 상황 → 개념 → 판단 기준 → 실제 적용
```

글은 원고에 실제로 있는 재료에서 시작한다. 확인된 경험이 있으면 장면과 행동을 먼저 쓰고, 경험이 없으면 문제 상황이나 자료에서 시작한다. 모든 글에 관점 이동을 강제하지 않는다.

### 반복 확인된 중심어

| 중심어 | 쓰는 장면 |
|---|---|
| 기준 | 무엇을 선택하거나 구분해야 할 때 |
| 구조 | 요소가 어떻게 연결되어 작동하는지 설명할 때 |
| 판단 | AI와 사람이 맡을 일을 나눌 때 |
| 흐름 | 일이 어떤 순서로 이어지는지 보여줄 때 |
| 맥락 | 같은 자료나 지시가 상황에 따라 달라지는 이유를 설명할 때 |
| 반복 | 시간이 들고 결과 편차가 생기는 작업을 말할 때 |
| 설계 | 시작 전에 순서·역할·조건을 정할 때 |
| 정리 | 자료·생각·작업을 다시 쓸 수 있는 상태로 바꿀 때 |

이 단어도 반복하면 분석문처럼 들린다. 한 문단에서 중심어 하나만 남기고, 다음 문장은 실제 장면이나 행동으로 풀어 쓴다.

### 조건이 있을 때 쓰는 판단어

`편차`, `거리`, `흔들림`, `관점 이동`은 실제 원문에서 반복 빈도가 낮았다. 공용 중심어로 자동 삽입하지 않는다. 원문·프로젝트·승인 예문에 있거나 해당 의미를 다른 말로 바꾸기 어려울 때만 사용한다.

저빈도라는 이유만으로 금지하지는 않는다. `04-examples.md`처럼 실제 경험과 작업 맥락에 붙어 있으면 분석어도 유지한다.

### 반복 확인된 전환어

`그런데`, `하지만`, `다만`, `막상`, `매번`, `또`, `처음부터`, `실제로`, `돌이켜보면`은 승인 원문과 반복 원문에서 장면과 판단을 잇는 말로 확인되었다.

- 기대와 실제가 달라지는 지점에서 사용한다.
- 시간·인과·범위가 바뀌지 않으면 습관적으로 넣지 않는다.
- 모든 문단을 같은 전환어로 시작하지 않는다.
- 원문에 더 자연스러운 말이 있으면 원문을 우선한다.

## 3. 표현 선택의 세 가지 조건

표현을 고를 때 세 가지를 함께 본다.

1. **의미 적합성** — 말하려는 내용과 정확히 맞는가
2. **목소리 적합성** — 홍작가가 실제로 쓸 법한가
3. **문단 역할 적합성** — 문단의 판단을 앞으로 움직이는가

문법적으로 맞고 자연스러워도 세 번째 조건을 통과하지 못하면 뺀다. 장식적인 분석 문장은 글을 좋아 보이게 만들지만, 글쓴이의 판단은 약하게 만든다.

## 4. 낯선 표현과 대체 방향

### 컨설팅·시장 분석식 표현

| 피할 표현 | 대체 방향 |
|---|---|
| 포지션 | 역할, 자리, 어디에 쓰이는지 |
| 무게중심이 이동한다 | 이제 모든 일을 그 안에서 처리하지 않게 되었다 |
| 패러다임 전환 | 판단 기준이 달라졌다, 일하는 방식이 바뀌었다 |
| 사용자 여정 | 사용자가 실제로 거치는 순서 |
| 가치 제안 | 무엇이 달라지는지, 왜 선택하는지 |
| 생산성 레이어 | 반복 작업을 줄이는 단계 |
| 워크플로우 허브 | 일을 모아 처리하는 곳, 작업의 중심 폴더 |
| 운영 환경 | 반복해서 돌리는 방식, 일을 맡기는 방식 |
| 작업 구조 | 일을 처리하는 흐름, 반복되는 절차 |
| 에이전트 환경으로 흡수된다 | 다른 에이전트가 그 일을 이어받기 시작했다 |
| 비개발자용 진입점 | 처음 AI 파일 작업을 익히는 단계 |
| 단발 파일 정리 | 간단한 파일 작업, 한 번 맡기는 파일 작업 |

### AI 제품 소개식 표현

| 피할 표현 | 대체 방향 |
|---|---|
| 강력한 도구 | 파일을 읽고 고치는 도구, 여러 단계를 이어서 처리하는 도구 |
| 혁신적인 방식 | 기존 방식과 달라진 지점을 직접 설명한다 |
| 완벽한 자동화 | 사람이 판단할 지점을 남긴 자동화 |
| 획기적인 변화 | 어떤 단계가 줄거나 역할이 달라졌는지 말한다 |
| 놀라운 결과 | 수치·시간·전후 비교를 제시한다 |
| 무한한 가능성 | 실제로 가능한 작업 범위를 적는다 |
| 생산성을 극대화한다 | 반복 입력이나 검토 단계를 줄인다 |
| 업무를 혁신한다 | 어떤 업무가 어떤 순서로 바뀌는지 말한다 |

### 의미가 흐린 분석 표현

| 피할 표현 | 문제 | 대체 방향 |
|---|---|---|
| 경계가 흐려진다 | 무엇이 달라졌는지 모호하다 | 역할이 다시 나뉜다, 구분 기준이 달라진다 |
| 생태계가 확장된다 | 실제 변화가 보이지 않는다 | 연결되는 도구·사용 장면을 적는다 |
| 본질적으로 | 근거 없이 결론을 키운다 | 바로 판단 문장으로 들어간다 |
| 새로운 국면 | 변화의 내용이 없다 | 이전과 지금을 비교한다 |
| 중요한 시사점 | 판단을 독자에게 미룬다 | 무엇을 기준으로 봐야 하는지 쓴다 |
| 의미가 있다 | 의미의 내용을 말하지 않는다 | 어디에 다시 쓰이는지, 무엇이 달라지는지 적는다 |

## 5. AI식 약한 문장을 바꾸는 법

| 약한 문장 | 바꾸는 기준 | 홍작가식 방향 |
|---|---|---|
| 활용할 수 있습니다 | 실제 사용 장면 | 이때 씁니다 / 이 작업에 붙입니다 |
| 도움이 됩니다 | 달라지는 결과 | 다시 설명하는 시간이 줄어듭니다 |
| 효율적으로 처리합니다 | 줄어드는 단계 | 같은 양식을 매번 새로 만들지 않습니다 |
| 쉽게 시작할 수 있습니다 | 시작 조건 | 폴더 하나와 규칙 문서 한 장이면 시작합니다 |
| 빠르게 작성합니다 | 시간 또는 단계 | 10분 안에 초안 구조를 만듭니다 |
| 중요합니다 | 빠지면 생기는 문제 | 이 기준이 없으면 결과가 매번 달라집니다 |
| 필요합니다 | 필요한 조건 | 반복 작업이라면 기준을 파일로 남겨야 합니다 |
| 다양한 결과물 | 실제 결과물 이름 | 블로그 글, 강의 메시지, 책의 질문으로 나뉩니다 |
| 이를 통해 | 동작을 바로 연결 | 삭제하고 다음 행동을 바로 쓴다 |
| 결과적으로 | 판단을 바로 제시 | 앞 문장과 직접 연결하거나 문장을 나눈다 |

## 6. 승인 원문에서 확인된 문장 이동

생성한 대표 문장을 홍작가 문체의 정답처럼 반복하지 않는다. 실제 문장의 모양은 `04-examples.md`를 우선한다.

### 실행이나 장면으로 시작한다

> 클로드 스킬을 만들어 보려고 빈 파일을 열었습니다. 그런데 첫 줄부터 막힙니다.

> 어제는 AI 책쓰기 컨설팅 첫 회차를 진행했다.

### 대화 속 문장을 자신의 이야기로 연결한다

> 오늘 채팅 중에 나온 말이기도 합니다. 저의 이야기기도 하고요

대화·댓글·다른 사람의 말에서 시작하더라도 실제로 자신의 경험과 맞닿아 있으면, 출처와 주체를 짧게 밝힌 뒤 현재 행동으로 이어간다. 남의 말을 곧바로 자신의 경험처럼 바꾸지 않는다.

### 익숙한 말로 기대를 꺾는다

> 하지만 한 달이 지나도 대부분은 계속 쓰지 않았다. 이유는 간단했다. 그들에게는 그 도구가 필요하지 않았던 것이다.

> 바이브 코딩으로 모든 시스템을 다 만들 수 있을 것 같았습니다. 그런데 몇 개 해보니 더 이상 아이디어가 떠오르지 않습니다.

### 자신의 판단과 적용 범위를 남긴다

> 책 다섯 권을 쓰며 쌓은 경험은 어디까지나 ‘홍작가에게 맞는 방식’이었다.

> 도구는 도구일 뿐, 혼자서 모든 걸 메우지는 못합니다.

### 현재의 행동·상태·결정으로 닫는다

> 올해 저는 그 방식을 접었습니다.

> 그래서 책을 쓸 때는 빈 화면에서 시작하지 않습니다.

피할 시작과 마무리:

```text
오늘은 ~에 대해 알아보겠습니다.
최근 ~가 주목받고 있습니다.
아래와 같이 정리했습니다.
지금 바로 시작해보세요.
이상으로 세 가지를 알아보았습니다.
도움이 되었으면 좋겠습니다.
앞으로 더욱 중요해질 것입니다.
```

## 7. 문단 구성 기준

문단을 일정한 문장 수나 단어 수에 맞추지 않는다. 아래 흐름은 자주 나타나는 선택지이며 고정 형식이 아니다.

```text
짧은 관찰이나 행동
→ 조금 긴 설명
→ 짧은 판단 또는 다음 장면
```

- 같은 길이의 문장을 세 번 이상 이어 쓰지 않는다.
- 자연스럽게 이어지는 문장을 규칙에 맞추기 위해 억지로 자르지 않는다.
- 한 문장마다 줄을 바꾸지 않는다.
- 모든 문단 끝에 판단문을 붙이지 않는다.
- 문단마다 중심 판단 하나만 남긴다.
- 표와 목록은 비교·선택·절차가 있을 때만 쓴다.

## 8. 채널별 표현 차이

| 채널 | 표현 기준 |
|---|---|
| 블로그 | 검색 질문을 받되, 정보 나열보다 판단 기준을 남긴다. H2는 기능명이 아니라 독자가 가져갈 문장으로 쓴다. |
| 페이스북 | 첫 문단에서 장면과 판단을 빠르게 연결한다. 소제목보다 문단 흐름과 리듬을 우선한다. |
| 브런치 | 설명을 줄이고 경험과 시선의 이동을 더 길게 가져간다. 결론을 서둘러 닫지 않는다. |
| 에세이 | 개념 설명보다 장면·감각·거리 변화를 우선한다. 판단어를 과하게 반복하지 않는다. |
| 책 원고 | 한 문장보다 챕터 전체의 반복과 논리 흐름을 먼저 본다. 같은 표현을 여러 장에서 반복하지 않는다. |
| 일반 콘텐츠 | 목적·독자·분량을 먼저 확인하고, 설명과 판단의 비율을 조정한다. |

채널은 구조를 바꾸지만 홍작가의 판단 이동은 유지한다.

## 9. 경험과 인용의 주체

- 사용자가 직접 경험했다고 밝힌 내용만 1인칭 경험으로 쓴다.
- 제3자의 댓글·발언·후기를 홍작가의 경험처럼 바꾸지 않는다.
- 다른 사람의 발언은 간접 인용하거나 출처를 분리한다.
- AI가 일반적인 사례를 만들어 `제가 해보니`로 쓰지 않는다.
- 경험이 없으면 관찰, 자료, 사례로 한계를 분명히 한다.

## 10. 초기 단계와 최종 단계 분리

### 방향·구조 단계

- 표현을 너무 빨리 매끈하게 만들지 않는다.
- 주제, 독자, 문제, 판단, 흐름을 먼저 맞춘다.
- 낯선 단어가 있어도 구조를 잡는 동안에는 후보로 표시할 수 있다.

### 최종 표현 단계

- 용어·표현 소유감 패스를 별도로 실행한다.
- 사용자가 제공한 단어와 수정 이력을 다시 본다.
- 낯선 분석어·컨설팅어·AI식 표현을 걷어낸다.
- 단순히 쉬운 말로 바꾸지 않고 문단의 판단을 보존한다.

## 11. 사용자 교정이 들어왔을 때

사용자가 “내가 쓰는 말이 아니다”, “표현이 낯설다”, “이 말은 어색하다”고 하면 다음 순서로 처리한다.

1. 의미가 어긋났는지 확인한다.
2. 목소리와 어휘가 낯선지 확인한다.
3. 문단에서 꼭 필요한 표현인지 확인한다.
4. 대체 표현 2~4개를 제시한다.
5. 하나를 추천하고 전체 문장에 넣어 확인한다.
6. 반복될 기준이면 이 사전에 교정 사례를 추가한다.

새 개념을 임의로 덧붙이지 않는다. 사용자의 교정은 문장 수정이 아니라 어휘 기준을 배우는 자료로 본다.

### 칼럼 퇴고에서 확인된 표현 기준

홍작가는 방법을 길게 설명하기보다 실제로 겪은 불편과 처음 품었던 기대를 먼저 쓴다. 독자가 상황을 이해한 뒤 판단에 도달하도록 하고, 후반부에서 같은 결론을 다시 설명하지 않는다.

- 같은 뜻의 동사가 이어지면 하나만 남긴다.
- `~한 작업이었습니다`, `~하는 부분이었습니다`처럼 명사 뒤에 `이었습니다`를 붙여 길게 닫지 않는다. 동작과 판단이 분명하면 `체감했습니다`, `확인했습니다`, `바꿨습니다`처럼 동사로 직접 끝낸다.
- 한 문단에서 `~했습니다·~이었습니다`가 같은 호흡으로 반복되면 필요한 문장만 남기고 서술어를 짧게 바꾼다. 다만 모든 종결을 기계적으로 줄이거나 반말·메모체로 바꾸지는 않는다.
- 독립된 한 줄짜리 후기·도입 라벨은 문맥이 분명할 때 `~사용해본 후기입니다`보다 `~한 달 사용 후기.`처럼 압축할 수 있다. 다만 제목이 이미 기간과 후기 성격을 말하면 같은 정보를 반복하지 말고, 첫 문장에서 실제로 달라진 판단을 보여주거나 라벨을 뺀다.
- 도입은 제목을 다시 설명하는 준비 문장보다 실제 경험에서 얻은 현재 판단으로 시작한다.
- 대조와 여러 작업 단계가 한 문장에 함께 들어가면, 달라진 판단을 짧게 먼저 쓰고 작업 순서는 다음 문장으로 나눈다.
- `다릅니다`, `중요합니다`처럼 다음 문장이 이미 차이와 이유를 설명하는 예고 문장은 줄이고 실제 차이부터 쓴다.
- `LLM 위키·스킬·오케스트레이터` 같은 내부 용어는 처음 나올 때 사전식 정의를 붙이지 않고, 이 글에서 맡는 역할을 짧게 설명한다. 낯선 용어를 한 문장에 여러 개 겹치지 않는다.
- 메모리·스킬·작업 규칙에 피드백이 반영된다고 쓸 때는 자동으로 저장되는 것처럼 표현하지 않는다. 무엇을 남길지 고르고 반영하는 사용자의 판단을 문장 안에 둔다.
- 결말에서 `~하는 것. 이 과정에 있습니다`처럼 명사형 판단과 해설을 연달아 쓰지 않는다. `더합니다`, `쌓입니다`처럼 현재 행동이나 상태를 나타내는 동사로 한 번만 닫는다.
- 기능 설명보다 사용하면서 드러난 불편과 기대의 어긋남을 앞에 둔다.
- 사용자가 직접 고친 문장과 단어를 새로 만든 분석 표현보다 우선한다.
- 달라진 현재 행동을 보여줄 때는 막연한 시점인 `요즘 저는`보다 변화가 드러나는 `이제는`을 우선한다.
- 문단의 주체가 분명하면 `저는·저도·제가`를 문장마다 반복하지 않는다. 주체가 바뀌거나 책임을 분명히 해야 할 때는 생략하지 않는다.
- 후반에 방법과 결론이 반복되면 한두 개의 짧은 관찰 문단으로 압축한다.
- 마지막은 요약이나 행동 촉구보다 현재 달라진 생각이나 작업 태도로 닫는다.
- 독자 관점의 결말에서는 독자가 최종 원고에서 확인할 수 없는 편집 과정을 읽는 것처럼 표현하지 않는다. `무엇을 남기고 버렸는지`보다 `무엇을 중요하게 보았고, 어떤 판단을 자신의 말로 남겼는지`처럼 최종 글에서 드러나는 관심과 판단을 쓴다.
- AI 활용의 긍정적 확장을 쓰는 글에서는 `일을 줄일 줄 알았다 → 실제로는 줄지 않았다`는 부정 대조를 억지로 넣지 않는다. 실제로 늘어난 일·서비스·수익 모델·기회부터 쓴다.

| 피할 표현·구성 | 홍작가식 수정 방향 |
|---|---|
| `고민하고 생각합니다` | `고민합니다` — 같은 뜻의 동사 반복을 걷어낸다 |
| `글쓰기는 헤르메스의 자기개선이 가장 먼저 체감된 작업이었습니다` | `글쓰기에서 헤르메스의 자기개선을 가장 먼저 체감했습니다` — `작업이었습니다`를 빼고 실제 동작으로 바로 끝낸다 |
| 제목과 같은 뜻의 `헤르메스 에이전트 한 달 사용 후기.` | `한 달 동안 써보니, 헤르메스는 설치로 완성되는 도구가 아니었습니다.` — 기간 정보만 반복하지 않고 한 달 뒤의 판단을 바로 보여준다 |
| 독립 도입의 `헤르메스 에이전트를 한 달 동안 사용해본 후기입니다` | 제목에 기간 정보가 없고 라벨이 필요할 때만 `헤르메스 에이전트 한 달 사용 후기.`처럼 압축한다 |
| `질문에 답을 받는 데서 끝나는 것이 아니라 글감을 찾고, 조사하고, 초안을 쓰고, 퇴고해 한 편의 결과물로 마무리하는 과정 전체를 함께 다루게 됐습니다` | `이제는 질문에 답을 받는 데서 끝나지 않습니다. 글감을 찾고 조사해 초안을 쓰고, 퇴고해 한 편으로 마무리하는 전 과정을 함께 다룹니다.` — 변화와 작업 순서를 두 문장으로 나눈다 |
| `강의 제작은 다릅니다. 글 한 편보다 호흡이 길고…` | `강의 제작은 글 한 편보다 호흡이 깁니다.` — 예고형 판단을 빼고 실제 차이부터 쓴다 |
| `스킬 하나의 완성도만큼 스킬과 스킬을 잇는 파이프라인과 전체 순서를 관리하는 오케스트레이터가 중요합니다` | `각 단계의 작업법인 ‘스킬’ 하나를 잘 만드는 것만큼, 여러 스킬을 순서대로 잇고 전체 진행을 관리하는 ‘오케스트레이터’도 중요합니다.` — 겹치는 용어를 줄이고 역할을 바로 풀어준다 |
| `그 피드백은 스킬과 기억, 작업 규칙에 남아 다음 결과에 반영됩니다` | `사용자가 남길 기준을 골라 스킬과 기억, 작업 규칙에 반영하면, 그 내용이 다음 작업의 기준이 됩니다.` — 자동 반영처럼 보이지 않게 사용자의 선택을 밝힌다 |
| `다음 기준을 더하는 것. 제가 경험한 자기개선은 이 과정에 있습니다` | `다음 기준을 더합니다. 제가 경험한 자기개선은 이렇게 쌓입니다.` — 명사형 결론과 해설의 반복을 동사형으로 줄인다 |
| `요즘 저는 글을 쓰거나 강의를 준비할 때` | 변화한 현재 행동이 중심이면 `이제는 글을 쓰거나 강의를 준비할 때`로 시작한다 |
| `그동안 저도`, `제가 할 수 있는 일은` | 주체가 이미 분명하면 `그동안`, `할 수 있는 일은`으로 줄인다 |
| `새로운 일의 재료가 되어지고 있습니다` | `새로운 일의 재료가 되고 있습니다` 또는 `새로운 일의 재료로 쓰이고 있습니다`처럼 이중 피동을 걷어낸다 |
| 기능과 작동 방식을 여러 문단으로 설명 | 실제로 무엇을 기대했고 어디서 어긋났는지 먼저 쓴다 |
| 후반부에 방법·주의사항·결론을 각각 반복 | 필요한 판단만 남기고 한두 문단으로 닫는다 |
| 소개 글의 마지막에서 활용 과정과 장점을 다시 설명 | 이미 본문에서 설명한 내용은 되풀이하지 않고, 현재 달라진 행동과 결과만 한두 문장으로 남긴다 |
| `자기개선 기능이 작동합니다` | `내가 일하는 방식과 기준을 남겨야 다음 작업이 달라졌습니다`처럼 경험으로 바꾼다 |
| `AI가 일을 줄일 줄 알았지만 실제로는 줄지 않았다` | `AI를 활용하면서 할 수 있는 일이 늘었고, 새로운 서비스·수익 모델·기회가 보이기 시작했다`처럼 현재의 긍정적 변화를 바로 쓴다 |
| `AI에 상당 부분 의존하고 있습니다` | `그 과정을 이제 혼자 감당하지 않습니다`, `AI와 일의 무게를 나눕니다`처럼 실제로 나눠 맡는 일을 보여준다. 절실함은 `AI 없이 예전 방식으로 이 과정을 다 해내기는 어렵습니다`처럼 현실적인 한계로 남긴다 |
| `AI가 제 삶을 대신하지는 않습니다 → 곁에 두어야 합니다 → 있으면 좋은 도구가 아닙니다`처럼 같은 뜻을 반복 | `판단과 책임까지 AI에 맡기는 것은 아닙니다. 하지만 예전 방식만으로 지금 하는 일을 이어가고 새로운 일을 준비하기는 어렵습니다. 그래서 AI는 앞으로도 제 일을 계속하고 다음 수입과 기회를 만들기 위해 꼭 필요한 생존 도구가 됐습니다.`처럼 책임·현실적 한계·현재 판단을 한 번씩만 쓴다 |
| `수많은 경험과 자료는 엄청난 기회가 되었습니다` | `쌓아온 경험과 자료는 지난 기록으로 머물지 않고 강의 자료·책의 아이디어·새로운 일의 재료가 됩니다`처럼 기회의 내용을 구체적으로 쓴다 |
| `독자는 그 가운데 글쓴이가 무엇을 남기고 버렸으며, 어떤 판단을 자신의 이름으로 책임졌는지를 읽습니다` | `독자는 그 안에서 글쓴이가 무엇을 중요하게 보았고, 어떤 판단을 자신의 말로 남겼는지를 읽습니다`처럼 독자가 최종 원고에서 확인할 수 있는 관심과 판단을 쓴다. 삭제된 문장이나 편집 과정까지 독자가 읽는 것처럼 표현하지 않는다 |
| 분석적인 최종 요약 | `이렇게 저는 AI 에이전트와 일하는 법을 다시 배우고 있습니다`처럼 현재의 관찰로 마무리한다 |

## 12. 프로젝트별 표현사전 만들기

책·연재·장기 콘텐츠처럼 주제와 독자가 달라지면 공용 사전 위에 프로젝트별 표현사전을 둔다.

권장 파일명:

```text
글쓰기표현사전_{프로젝트명}.md
```

필수 항목:

```markdown
# 글쓰기표현사전 — {프로젝트명}

## 독자와 글의 거리
## 프로젝트 핵심 문장
## 반복해서 쓸 용어
## 피할 표현과 대체어
## 경험·사례의 주체
## 제목·소제목 기준
## 마무리 기준
## 사용자 교정 이력
```

프로젝트 사전에는 그 글에서만 필요한 용어를 넣는다. 한 프로젝트의 예외를 공용 사전에 바로 올리지 않는다. 여러 작업에서 반복 확인된 표현만 공용 사전에 승격한다.

## 13. 최종 점검 체크리스트

- [ ] 사용자가 직접 쓴 단어를 불필요하게 낯선 말로 바꾸지 않았는가
- [ ] 문장이 자연스럽더라도 홍작가가 실제로 쓸 법한가
- [ ] 컨설팅·시장 분석·제품 소개식 표현이 남지 않았는가
- [ ] 중심어인 기준·구조·판단도 과하게 반복하지 않았는가
- [ ] 방법보다 문제 지점과 판단 기준이 먼저 나왔는가
- [ ] 구체적인 장면·조건·수치 없이 추상어만 남지 않았는가
- [ ] 제3자의 경험을 홍작가의 1인칭 경험으로 바꾸지 않았는가
- [ ] 마무리가 요약이나 행동 촉구가 아니라 현재 판단·행동·상태 중 하나로 끝나는가
- [ ] AI 흔적 제거 과정에서 원문의 의미와 온도를 훼손하지 않았는가
- [ ] 최종 문장이 매끈한 문장보다 글쓴이가 소유할 수 있는 문장에 가까운가
